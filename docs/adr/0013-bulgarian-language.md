# ADR 0013 — Bulgarian language: content, answers and UI

Status: accepted · Date: 2026-10-22 · Builds on ADR 0003, 0009 and 0010

## Question

The first market is Bulgaria. What does it take for Bulgarian documents to be
found, Bulgarian questions answered in Bulgarian, and the UI usable in
Bulgarian?

## Findings (bugs fixed)

1. **Bulgarian text was unsearchable.** The tokenizer kept only `[a-z0-9]`,
   so Cyrillic produced no terms at all. This affected lexical retrieval,
   the evidence score and the fake model.
2. **Cyrillic file names collided.** Document IDs replaced every non-ASCII
   character with `_`, so `отпуски.md` and `договор.md` could map to the same
   ID, and one would overwrite the other.
3. **Long IDs were invalid.** The long-name branch used `~`, which the ID
   schema rejects.

## Decisions

### Content and retrieval

- **Tokenizer:** Unicode letters and digits. Lower case, with combining
  marks removed (é → e, й → и), applied identically to documents and
  questions. English behaviour is unchanged (tests).
- **Bulgarian stemmer** (in the spirit of Lucene's `BulgarianStemmer`): it
  removes a definite article, then a plural ending, then a final vowel, and
  always keeps at least three letters.
  - Matches проектът / проекта / проекти / проектите, and сметката / сметки.
  - The short articles `-та/-то/-те` are stripped only after a vowel, so
    проекта stays a masculine noun.
  - It does **not** handle verb and noun derivation (забави vs забавено).
    Semantic scoring and real models cover that.
- **Bulgarian stopwords;** each token uses its own script's rules.
- **Document IDs:** names with non-ASCII characters are transliterated with
  the official Bulgarian system and get a short hash of the original name,
  for example `handbook/отпуски.md` → `team-share:handbook_otpuski.md--1ea0c79a`.
  ASCII names are unchanged, so nothing already indexed is re-keyed.

### Answers

- A platform rule tells every agent to answer **in the language of the
  question**, keeping names, figures and citation markers.
- The platform's own messages (not enough evidence, time limit, error,
  cancelled) are returned in Bulgarian when the question is Bulgarian
  (`detectLanguage`: majority of letters Cyrillic).

### UI

- `packages/ui` holds one typed dictionary (`i18n.tsx`). Bulgarian must
  translate every key, or the build fails. It provides `I18nProvider`,
  `useT()` (`t`, `tm` for dynamic keys, and `when` for locale dates), and
  an **EN | БГ** switch in the header.
- The choice is saved in the browser. The default follows the browser's
  language. `<html lang>` follows the choice.
- Agents can carry `localized` display names and descriptions; both agents
  have Bulgarian ones.
- Manrope and JetBrains Mono now load their Cyrillic subsets.
- **Not translated, because they are data:** source titles, tracker
  operation and risk texts generated by capabilities, principal names,
  document content.

## Evidence

- `packages/knowledge/test/bulgarian.test.ts`: tokens, stem families,
  stopwords, language detection, collision-free and schema-valid IDs, and
  English unchanged.
- `apps/api/test/api.test.ts`, "Bulgarian documents and questions":
  - a Bulgarian question gets a Bulgarian answer citing the Bulgarian
    document
  - the denied user gets the Bulgarian refusal and nothing about Atlas
  - all-staff users can read the Bulgarian leave policy
- Two synthetic Bulgarian fixtures: `handbook-otpuski-bg` (all-staff) and
  `atlas-status-bg` (atlas-team).
- Checked in the browser: Bulgarian UI, a Bulgarian question answered and
  cited, Bulgarian dates.

## Not verified, and recommendations

- **Real-model Bulgarian quality is not measured.** `qwen3:4b` and
  `qwen2.5:3b` (LightRAG extraction) are weak in Bulgarian. Run a Bulgarian
  eval set before a pilot.
- **Embeddings:** `nomic-embed-text` is English-centric. For Bulgarian
  semantic scoring and LightRAG vectors, use a multilingual model such as
  `bge-m3` (`EMBEDDING_MODEL`, `LIGHTRAG_EMBEDDING_MODEL`). Changing it
  needs a full re-index, and a re-calibration (ADR 0010, Decision 4).
- **LightRAG** `SUMMARY_LANGUAGE` is English. Entity summaries of Bulgarian
  documents should be Bulgarian when most of a partition is Bulgarian.
